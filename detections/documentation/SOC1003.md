# SOC1003 — Windows non-machine user account created

## Detection record

| Field | Value |
|---|---|
| Detection ID | `SOC1003` |
| Purpose | Identify creation of a Windows user identity that is not named like a machine account. |
| Log source | Windows Security event 4720 collected by the Wazuh agent. |
| Detection logic | Wazuh rule 100102 extends built-in account-creation rule 60109 and excludes names ending in `$`. The Sigma rule expresses the same event and machine-account filter. |
| Severity | Wazuh level 9; Sigma high. |
| MITRE ATT&CK | T1136.001 — Create Account: Local Account. |
| Status | Test. |

## Known false positives

- Approved help-desk or identity-administration work.
- Application service-account provisioning.
- Authorized lab validation.

Event 4720 can describe local or domain-scoped activity depending on the reporting host and account context. Analysts must verify the target domain and endpoint role.

## Validation method

Run `endpoints/windows/Generate-Phase4TestEvents.ps1`. It creates, disables, and immediately deletes `soc_phase4_test` using a random lab-only password. Confirm Wazuh rule 100102 and verify the account no longer exists. The negative generator uses a temporary name ending in `$`; it must remain a built-in account event and not match rule 100102.

## Response recommendation

Confirm the request or change record, creating principal, target domain, group membership changes, and subsequent logons. Escalate unexplained privileged or service-like accounts. Account disablement remains approval-gated and is not performed by this detection.

## Tuning notes

Prefer identity-aware exclusions for approved provisioning systems and expected account naming conventions. Retain visibility into service accounts and review the filter whenever naming or provisioning policy changes.
