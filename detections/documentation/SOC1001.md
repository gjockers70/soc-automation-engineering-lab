# SOC1001 — Repeated invalid-user SSH login attempts

## Detection record

| Field | Value |
|---|---|
| Detection ID | `SOC1001` |
| Purpose | Identify repeated SSH attempts against nonexistent Linux accounts from one source address. |
| Log source | Linux `sshd` authentication messages collected by the Wazuh agent. |
| Detection logic | Wazuh rule 100100 correlates five matches of built-in invalid-user rule 5710 from the same source IP within 60 seconds. The Sigma rule represents the portable base event; backend correlation is required to reproduce the threshold. |
| Severity | Wazuh level 10; high-priority triage. |
| MITRE ATT&CK | T1110 — Brute Force. |
| Status | Test. |

## Known false positives

- A user repeatedly mistyping an account name.
- Stale automation, monitoring, or deployment credentials.
- An approved authentication-control test.

The documentation-only address `198.51.100.44` is reserved for validation and should be excluded from production conclusions, not from lab rule execution.

## Validation method

Run `endpoints/linux/generate_phase4_test_events.sh` on `ubuntu-web-01`. It emits six synthetic authentication messages. Confirm Wazuh rule 100100 appears in `alerts.json` and rerun `docker/wazuh/validate_phase4_detections.sh`. The negative generator emits only four events from a different TEST-NET address and must not trigger rule 100100.

## Response recommendation

Review the source address, targeted account strings, successful authentications, endpoint role, and prior sightings. Escalate if attempts precede a success or target sensitive naming patterns. Do not block the address automatically; any containment proposal requires analyst approval in a later phase.

## Tuning notes

Tune frequency and timeframe only after measuring expected administrative noise. Prefer allow-listing a documented scanner identity over globally raising the threshold. Review the rule after authentication-system or SSH-policy changes.
