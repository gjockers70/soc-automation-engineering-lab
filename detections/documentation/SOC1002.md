# SOC1002 — PowerShell launched with an encoded command

## Detection record

| Field | Value |
|---|---|
| Detection ID | `SOC1002` |
| Purpose | Identify PowerShell process creation where command content is obscured with an encoded-command switch. |
| Log source | Windows Security event 4688 with process command-line auditing enabled. |
| Detection logic | Wazuh rule 100101 extends built-in process-creation rule 67027 and matches accepted abbreviations of PowerShell's encoded-command flag followed by Base64-like content. The Sigma rule additionally constrains the image to PowerShell or PowerShell Core. |
| Severity | Wazuh level 10; Sigma high. |
| MITRE ATT&CK | T1059.001 — PowerShell. |
| Status | Test. |

## Known false positives

- Approved administrative scripts.
- Software-deployment or device-management tooling.
- Security validation frameworks using encoded PowerShell.
- QEMU Guest Agent administration in this lab, whose script runner deliberately uses an encoded PowerShell wrapper.

Encoding is not proof of malicious intent; it raises investigation priority because it reduces immediate command-line readability.

## Validation method

Run `endpoints/windows/Generate-Phase4TestEvents.ps1` on `win11-01`. The script launches a harmless encoded `Write-Output` command, waits for completion, and performs no persistence or security-control changes. Confirm Wazuh rule 100101 and run the phase validator. The negative generator launches ordinary PowerShell without an encoded flag; it must remain a built-in process event and not match rule 100101.

## Response recommendation

Decode the Base64 as UTF-16LE in a non-executing analysis step, review parent process and user context, compare with approved automation, and search nearby PowerShell 4104 records. Do not execute decoded content or terminate the process automatically.

## Tuning notes

The live lab confirmed QEMU Guest Agent administration as an expected match. Create narrow exclusions using signed script identity, known management parent processes, and approved service accounts. Avoid excluding all encoded PowerShell because the flag is a useful behavioral signal.
