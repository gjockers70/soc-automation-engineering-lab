# Phase 17 Implementation

## Objective

Phase 17 turns the phase-by-phase engineering record into a concise, evidence-backed portfolio presentation without overstating the lab as professional employment or commercial-product experience.

## Changes

- Reorganized the README around the problem, architecture, alert lifecycle, stack, evidence, playbooks, security controls, transferability, limitations, and repository navigation.
- Added SOC_OPERATIONS.md with the complete alert-to-closure analyst procedure.
- Added a claim-to-evidence index and an exact SOC engineer requirement/gap matrix.
- Added a careful Tines, ThreatQ, and Andesite concept mapping with explicit non-equivalence.
- Added consolidated known limitations and production-scale changes.
- Added architecture, sequence, approval, and sanitized dashboard visuals.
- Added automated checks for required documentation, portfolio sections, commercial claims, honest gaps, and diagram consistency.

## Evidence policy

The presentation uses only implemented capabilities supported by committed configuration, automated tests, or sanitized live validation. Live administrative screenshots are not committed because they can expose credentials, endpoint identifiers, case data, or internal service details. The dashboard visual is derived from versioned Grafana provisioning and contains no runtime data.
